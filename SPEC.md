=== SPEC: exec-impact ===

GOAL
Estimate market impact from real crypto trade data and test whether Almgren-Chriss
optimal execution beats TWAP and VWAP at reducing implementation shortfall, across
order sizes and horizons. Output a reproducible metrics table.

1. DATA
- Source: data.binance.vision spot aggTrades daily zips for BTCUSDT and ETHUSDT,
  one fixed, fully completed month (configurable in config.yaml).
- Verify each file against its .CHECKSUM. Cache as parquet under data/ (gitignored).
  Provide scripts/download_data.py so anyone can rebuild.
- Handle schema differences: files may have a header or not, and timestamps may be
  milliseconds or microseconds. Detect and normalize to UTC datetime.
  Aggressor side: is_buyer_maker == True means the SELLER was the aggressor.
- Build 1-minute bars: last price, volume, signed volume (buy minus sell aggressor),
  trade count, realized volatility.

2. IMPACT MODEL
- Per interval (try 1m, 5m, 15m), regress normalized return on signed flow:
    r / sigma = Y * sign(Q) * (|Q| / V)^delta
  where sigma is trailing volatility and V is trailing average volume, both computed
  using only prior data. Fit delta freely (log-log, Huber robust regression) and
  compare against fixed delta = 0.5. Report delta with bootstrap 95% CI.
- Decompose into temporary vs permanent: permanent = price change that persists
  k intervals after the flow, temporary = peak impact minus permanent.
- Stability: re-fit per week and per symbol; report parameter table and drift.
- Out-of-sample: fit on weeks 1-2, evaluate predictive R2 on weeks 3-4.
- Document the limitation: public trades give market-wide price response to flow,
  not the impact of our own order, and flow/price are simultaneous (endogeneity).

3. EXECUTION STRATEGIES
Parent order of X units (buy and sell), horizon T, N child slices.
- TWAP: equal slices.
- VWAP: slices proportional to an intraday volume profile estimated ONLY from the
  prior 7 days. Also include an "oracle VWAP" (uses realized volume) clearly labelled
  as an unattainable benchmark.
- Almgren-Chriss: closed-form linear-impact trajectory
    x_k = X * sinh(kappa*(T - t_k)) / sinh(kappa*T)
  with kappa from risk aversion lambda, sigma, and temporary impact eta (adjusted
  by permanent impact gamma). Linearize the sqrt-law impact around a reference order
  size and document how. STRETCH: numerically optimize a trajectory under the
  power-law temporary impact (scipy/cvxpy) and compare to the closed form.
- Sweep lambda over at least 6 values from near-zero to large.

4. SIMULATION AND EVALUATION
Two evaluation modes:
 (A) Tape replay: sample 500+ random start times across the month (same start times
     for every strategy, so comparisons are paired). Arrival price = last trade before
     start. Slice fill price = tape VWAP over the slice interval plus modeled temporary
     impact (from the calibrated model, using impact params fitted on PRIOR data only)
     plus accumulated permanent impact. State plainly that our order does not alter
     the tape.
 (B) Synthetic Monte Carlo: GBM prices plus the linear impact model, to verify AC
     achieves the best mean-variance utility under its own assumptions. This is a
     correctness check, not a performance claim.
Grid: order size as % of trailing ADV {0.01, 0.05, 0.1, 0.5, 1.0}; horizon {30m, 1h, 4h};
both symbols; buy and sell.
Metrics (per strategy, per grid cell):
- Implementation shortfall in bps (sign-adjusted so positive = cost): mean, std,
  95th percentile, CVaR95.
- Paired difference vs TWAP with bootstrap 95% CI and Wilcoxon p-value.
- Cost-vs-size curves, risk/cost efficient frontier (mean cost vs std of cost across
  lambda), and fees reported as a separate constant line (taker fee configurable).
- Headline table: "AC (best lambda) reduces mean shortfall by X bps (CI) vs TWAP at
  size Y", including cells where it does NOT help.

5. TESTS (pytest, must pass in CI)
- Every schedule sums exactly to X, is non-negative, and holdings are monotone.
- AC with lambda -> 0 matches TWAP; larger lambda is more front-loaded.
- VWAP weights sum to 1; changing FUTURE data does not change the schedule
  (no-lookahead test). Same for sigma and impact-parameter estimators.
- Parameter recovery: simulate data with known Y and delta, confirm the estimator
  recovers them within tolerance.
- Sign conventions: buy vs sell shortfall, aggressor side mapping, timestamp unit
  detection.

6. DELIVERABLES
- src/exec_impact/{data,bars,impact,schedules,simulate,metrics}.py, tests/, scripts/,
  config.yaml, Makefile (make data, make fit, make simulate, make report, make test).
- results/metrics.json and results/figures/*.png generated by `make report`.
- README: problem, method, results table, figures, assumptions, and an honest
  limitations section (no queue position, no hidden liquidity, no order book,
  our order does not move the tape, single month, crypto not equities).
- GitHub Actions workflow running ruff and pytest.
